# 专利创新点提取与撰写技能

> Version 1.2.0

从电力系统领域的软件工程项目中提取技术创新点，通过真实专利文献调研验证新颖性，经用户选定目标后撰写专利技术交底书。

## 安装

```bash
git clone https://github.com/Minggshen/patent-writer-skill.git "%USERPROFILE%\.claude\skills\patent-writer"
```

安装到用户级 skills 目录，重启 Claude Code 后通过对话中的关键词即可触发，所有项目均可使用。

## 工作方式

本技能分两个阶段工作，中间由用户决策：

**阶段一：创新点挖掘**
1. 深入探索项目工程目录
2. 识别候选技术创新点
3. 针对每个候选点检索真实专利和学术文献，验证新颖性
4. 输出 `创新点清单_[项目简称].md`

**用户决策**：从创新点清单中选定一个目标。

**阶段二：专利撰写**
5. 将选定的创新点升华为专利级技术方案
6. 按标准技术交底书格式撰写，输出两份文件：

| 文件 | 内容 |
|------|------|
| `创新点清单_[项目简称].md` | 候选创新点、调研验证、新颖性分析 |
| `专利初稿_[专利名称].md` | 专利正文（含公式、图表占位） |
| `专利附图说明_[专利名称].md` | 附图绘制说明（元素清单、色号、连接关系） |

## 适用领域

微电网、光伏发电、储能系统、负荷预测、故障诊断、优化调度、配电网规划等电力系统子领域。

**不适用**：机械结构、化学工艺、生物医药、通信协议等非电力系统领域。

## 触发方式

在对话中提到以下关键词即可触发：提取创新点、撰写专利、专利初稿、技术交底书、申请专利、专利挖掘、技术创新点、专利技术方案。

## 写作规范要点

- **引用真实性**：所有引用的专利和文献必须来自真实检索结果，严禁捏造
- **已有技术/产品的不足**：一整段流式叙述，不分小节、不编号列举
- **措辞规范**：使用"有待提升""存在不足""尚未""未充分考虑"等客观表述，严禁全盘否定
- **公式规范**：在需要数学表达的技术环节给出公式，每个公式独占一行并编号
- **图表数量**：至少 5-8 张图，图1必须为整体技术路线图
- **语言风格**：正式学术中文，使用"本发明"而非"我们"/"本文"

## 前置要求

- 需要可访问的项目工程目录（包含代码、文档、数据文件）
- 需要网络连接以检索真实专利和学术文献
- 用户应熟悉项目的技术方案，能在挖掘阶段选定目标创新点
