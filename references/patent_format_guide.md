# 专利初稿模板格式规范（详细参考）

此文件详细记录6个参考专利模板的格式特征，供撰写专利初稿时参考。

---

## 一、整体结构（各模板共有）

所有模板均遵循以下顺序：

1. **专利名称** — 标题
2. **发明人/申请人/地址** — （通常留空或占位）
3. **本专利的应用领域**
4. **本专利的任务/要解决的技术问题**
5. **已有技术/产品的不足**
6. **本专利的内容**（含总体方案+具体实施例+公式+图表）
7. **附图或图表**（集中列出）
8. **本专利的效果/有益效果**

---

## 二、各部分的详细格式特征

### 2.1 专利名称

格式：`一种基于[核心技术]的[具体应用][方法/策略/系统]`

模板1：计及不同绝缘缺陷信号传导极限距离的架空线路巡检定位策略
模板2：一种基于改进型ALA的构网型储能经济性配置方法
模板3：一种基于液态神经网络与注意力机制的励磁变压器故障诊断方法
模板4：一种基于VMD-NRBO优化神经网络融合法的络短期负荷预测方法
模板5：一种基于新能源出力误差采样校准的双层滚动精准调度方法
模板6：一种考虑光伏出力振荡性的多天气场景光伏发电预测方法

模式：`一种` + `基于/考虑/计及/融合` + `核心技术特征` + `的` + `应用领域` + `方法/策略/系统`

### 2.2 应用领域

- 1-2句话，精确到细分领域
- 格式："本发明涉及[领域A]与[领域B]，尤其涉及一种基于[核心技术]的[具体应用]。"
- 不泛泛说"电力系统"，而是具体到如"架空线路绝缘缺陷检测与巡检定位"、"短期光伏发电预测"

### 2.3 要解决的技术问题

**第一层：背景描述**
- 描述行业/设备/系统的运行环境
- 说明为什么这个问题重要
- 如果有多种因素交织，逐一说明
- 长度：2-4段

**第二层：具体任务**
- 明确列出要解决的2-4个子问题
- 有时用编号（1）（2）（3）列出
- 格式："本专利的任务是..."
- 子问题涵盖：数据质量、方法局限、场景适应性等

### 2.4 已有技术的不足

对每个现有技术，按此格式：
- **技术名称+原理**（1-2句）
- **不足**（1-3句，具体可验证的缺陷）

覆盖3-6种现有技术。常见被批评的现有技术：
- ARIMA/传统时序模型 → 无法处理非线性
- LSTM/GRU/RNN → 固定时间窗口，无法自适应
- SVM → 长期依赖捕获不足
- 单一传感器监测 → 无法捕捉耦合效应
- 固定式在线监测 → 成本高
- 人工巡检 → 效率低
- 经验选取参数 → 场景适应性差

**结尾总结**："因此，有必要提出一种..."

### 2.5 本专利的内容（技术方案）

此部分最长，包含所有技术细节。

**总体方案段落**：
- 用"本发明提出一种...方法/策略"开头
- 概述完整技术路线：首先→然后→最后
- 提及引用图1作为整体技术路线图

**具体实施例分节**：
按技术模块分节，每节包含：
1. 子问题引入
2. 方法描述
3. 数学公式（编号(1)(2)(3)...）
4. 图表引用（"如图X所示"）

**公式书写规范**（从6个模板中观察）：
- 所有公式有编号
- 每个符号在正文中定义
- 使用标准数学符号：Σ、积分、偏导∂、希腊字母
- 包含：目标函数、约束条件、状态方程、更新规则、损失函数
- 公式密度：整个技术方案部分至少10+个公式

**公式类型分布**：
- 信号处理类：分解模型、时频分析、能量计算
- 优化类：目标函数、约束条件、拉格朗日函数
- 深度学习类：网络状态方程、激活函数、损失函数、反向传播
- 概率类：概率分布、采样公式、隶属度计算

**图表引用规范**：
- 在相应文字的下方标注"图X [图题]"
- 图1总是整体流程图/技术路线图
- 图题要求描述性，不简单的"XX图"

**算法流程描述**：
- 逐步描述："步骤1: ..., 步骤2: ..., 步骤3: ..."
- 或分层次描述数据处理流程

### 2.6 附图或图表

集中列出所有图表：
```
图1 [标题]
图2 [标题]
...
```

图类型分布：
- 整体技术路线图/流程图（必有）
- 算法/模型结构图（必有）
- 数据处理流程图
- 结果对比图（损失曲线、准确率、电压对比等）
- 数据表格（场景分类表、参数表等）
- 混淆矩阵
- 成本分析图

### 2.7 有益效果

- 与"要解决的技术问题"呼应
- 逐条列出（2-5条），每条一段
- 包含量化指标：RMSE减少X%、准确率提高X%、投资回收期X年
- 说明因果：因为X → 所以Y
- 最后总结综合优势

## 三、语言风格特征

1. **用词**：正式学术中文
   - 用"本发明"而非"我们"/"本文"
   - 含有："基于"、"通过"、"利用"、"实现"、"从而"、"进而"、"由此"
   - 避免口语化表达

2. **句式**：复合句为主，逻辑关系清晰
   - 因果："由于...因此..."
   - 递进："不仅...还..."
   - 对比："相较于...本专利..."

3. **技术描述密度**：每段都包含具体技术内容，不空泛

4. **公式后的解释**：每个公式后都有"式中：[符号定义]"的解释文字

---

## 五、关键注意事项

1. 这是**技术交底书**，不是正式专利申请稿——不需要"权利要求书"章节
2. 公式需要准确，用户会用MathType重写——但仍要提供尽可能准确的数学表达
3. 图表需要具体的技术内容——不能只是占位符
4. 技术方案的描述要达到"本领域技术人员可复现"的程度
5. 创新点与现有技术的区别要说清楚
